# 설계 결정

## 서버 없는 정적 사이트

- **결정**: Astro로 빌드한 정적 파일을 GitHub Pages에 올린다. 서버·DB·계정이 없다.
- **이유**: 운영 비용 0원, 장애 지점 없음, 기여자가 로컬에서 `npm run dev` 하나로 전부 재현 가능.
- **대가**: 학습 기록이 브라우저에만 남는다(기기 간 동기화 없음). 면접 후기 제보처럼 서버가 필요한 기능은 나중에 별도 서비스로 분리한다. 후기 같은 개인 데이터는 이 레포에 절대 들어오지 않는다.

## BYOK (Bring Your Own Key)

- **결정**: AI 기능은 사용자가 자기 API 키를 넣어 브라우저에서 AI 회사 API를 직접 호출한다.
- **이유**: 공개 사이트에서 운영자 키로 AI를 열면 남용 비용을 감당할 수 없다. 프록시 서버를 두면 "서버 없음" 원칙이 깨지고 키 보관 책임이 생긴다.
- **보안 경계**: 키는 `localStorage` 에만 있다. 같은 출처의 스크립트는 읽을 수 있으므로 외부 스크립트(광고, 분석 도구)를 넣지 않는다. 공용 PC에서는 키 지우기를 안내한다.
- **어댑터 구조**: `src/lib/ai/providers.ts` 의 `Provider` 인터페이스(`chat(messages, settings, signal)`) 하나로 제공자를 갈아끼운다. 화면 코드는 `chat()` / `chatJSON()` 만 안다.

## 콘텐츠 = 마크다운 + 스키마

- **결정**: 한 호 = `content/issues/*.md` 하나. frontmatter는 Zod 스키마(`src/content.config.ts`)로 검사하고, CI가 PR마다 빌드해서 스키마 위반을 막는다.
- **이유**: 기여자는 코드를 몰라도 글만 쓰면 된다. 리뷰는 GitHub PR 그대로 쓴다. 정확성 검수 이력이 커밋으로 남는다.
- **출처 강제**: `sources` 는 최소 1개 필수. `seenIn`(실제 면접 등장)은 공개 URL이 있어야만 넣을 수 있다.

## 메일 발송

- **지금**: 뉴스레터 서비스(무료 요금제)에 구독 폼만 붙이고, 새 호가 나오면 요약 + 링크 메일을 직접 보낸다. 구독자 이메일은 그 서비스가 보관한다.
- **이유**: 구독자 개인정보, 수신거부, 발신 도메인 인증을 직접 떠안지 않으려고. "서버 없음" 원칙도 지킨다.
- **나중**: 구독자가 늘면 GitHub Actions → 메일 HTML 생성 → 이메일 발송 API로 직접 보내는 파이프라인으로 옮긴다. 그때 구독자 DB, 가입 확인 메일, 수신거부, SPF·DKIM을 함께 설계한다.
- **메일 본문엔 요약과 링크만**: 안 보고 설명하기는 사이트에서 해야 효과가 있어서, 메일에 전문을 넣지 않는다.

## 학습 흐름

읽기 → 글 접고 설명(인출 연습) → 꼬리질문 → 간격 반복(1/3/7일).
AI가 없으면 `keyPoints` 체크리스트로 스스로 채점하고, 꼬리질문은 frontmatter의 예시 답안을 보여준다. AI는 필수가 아니라 강화 장치다.
